# 💐 Bouquet — концепция

## Принципы

1. Компактное ядро, без установки приложения и без сборки.
2. Открывается в браузере на любой ОС, работает офлайн.
3. Данные выбранных локальных файлов остаются в браузере.
4. Функции и оформление добавляются плагинами — отдельными JavaScript-файлами.

## Структура интерфейса

Постоянная шапка просмотра: `[💐 Bouquet] [data / shop.db / purchases] [Открыть] [⚙]`. Логотип и путь находятся слева, действия открытия и настроек — справа. На узком экране путь переносится на вторую строку, действия остаются доступны. Пока данных нет, путь и кнопка открытия в шапке скрыты, большое действие «📂 Открыть» находится по центру рабочей области.

Путь показывает выбранный набор файлов или перетащенную папку, файл и выбранную таблицу, если таблиц несколько. Например: `Выбранные файлы / shop.db / purchases`. Родительские части кликабельны: набор возвращает к списку файлов, база — к списку таблиц. Текущая часть — обычный текст, клик ничего не делает. Стрелки назад и крестика закрытия файла в шапке нет. Кнопка «📂 Открыть» сразу вызывает стандартный системный диалог с множественным выбором файлов, без промежуточного окна. Отмена выбора сохраняет текущие данные и чтение; новая выборка заменяет их после подтверждения диалога.

В настройках файловый путь заменяется на `/ Настройки`, кнопки открытия и шестерёнка скрыты. Крестик после раздела и логотип возвращают к прежнему уровню просмотра с сохранением данных, поиска и прокрутки. Авторство видно только при наведении на иконку логотипа («💐 Bouquet, @vladaaar, 2026») и по ссылке внизу настроек. Название основного раздела в интерфейсе не показывается.

Страница «Настройки» содержит разделы в порядке: 🌐 Язык, 🔌 Плагины, 🎨 Темы оформления, ⏬ Чтение файлов. Языки и темы представлены отдельными карточками с кнопкой «Применить» и отметкой активного выбора, без выпадающих меню. Они не дублируются в общем списке плагинов. Кнопка загрузки `.js` в разделе плагинов подключает расширения всех категорий. Внизу настроек — ссылка @vladaaar, 2026. Дополнительные разделы интерфейсных плагинов доступны из настроек.

Вкладки меняют видимую панель без навигации и перезагрузки страницы. Панели создаются один раз и остаются в DOM. Переход из исследования в настройки и обратно сохраняет файл, выбранную таблицу, введённый запрос, результаты, порцию данных, раскрытые ячейки и прокрутку. Текущее чтение продолжается в фоне. Переход по логотипу возвращает к сохранённому просмотру.

Это сохранение состояния в текущей сессии страницы, а не восстановление после её перезагрузки.

## Исследование файлов

### Нет доступного файла

В центре рабочей области — большая кнопка «📂 Открыть». Она сразу открывает стандартный системный диалог с множественным выбором файлов. Одного выбранного файла достаточно; отдельной ссылки и диалога выбора папки нет. Файлы также можно перетащить в окно. Существующая поддержка перетаскивания папок сохраняется. Строка поиска и пустая таблица не отвлекают от выбора файла.

На `file://` браузер не даёт автоматически читать соседние файлы: показываем кнопку ручного выбора. При запуске через HTTP ядро проверяет файлы из `bouquet.files.json`. Несколько доступных файлов показываются списком, единственный открывается сразу. Если ни один не доступен, остаётся кнопка открытия. Доступность файла нельзя выводить только из наличия его имени в манифесте.

### Файл выбран или загружен

Если в папке или наборе выбранных файлов несколько файлов, в зоне просмотра появляется список с относительными путями, включая вложенные папки. До выбора содержимое локальных файлов не читается. Файл с несколькими таблицами сначала показывает список таблиц в той же зоне. Единственный файл или единственная таблица открывается сразу. Клик по родительской части пути в шапке возвращает на соответствующий уровень; возврат отменяет текущее чтение. Переход в настройки сохраняет выбранный уровень и состояние просмотра.

После выбора таблицы показываем первую порцию данных — до 100 строк, без ввода поискового запроса. Для прогрессивного источника читается первая порция, для CSV/TSV и текста файл пока разбирается целиком. Открытие и ошибки сопровождаются отдельным сообщением; ошибки показываются явно, остаётся возможность выбрать другой файл. Во время чтения область данных помечается `aria-busy`.

При выборе из списка файлов или таблиц строка статуса скрыта. Она отображается при открытии файла, чтении и просмотре данных.

Сверху рабочей области:

- Поиск, если подключён поисковый плагин; логотип находится только в шапке.
- Строка статуса непосредственно под поиском содержит только «Найдено · Просмотрено строк · Всего строк». Неизвестный итог не показывается; знак `≥` обозначает неполное количество совпадений. Имя таблицы остаётся в пути шапки. Таблицы выбираются списком непосредственно в зоне просмотра; выпадающего выбора таблицы нет.

Просмотрено — накопительное число проверенных записей для текущего запроса, включая несовпадения. При фильтрации в памяти проверяется вся таблица, без фильтра считается объём до текущей порции. Прогрессивные интерпретаторы возвращают `scanned` и сообщают его в `onProgress`; счётчик обновляется даже при отсутствии совпадений. CronosPro считает слоты банка, в том числе удалённые записи и записи других таблиц. На предыдущей порции показывается счётчик её курсора. Смена запроса, файла или таблицы начинает подсчёт заново.

### Поиск и отображение

Поиск фильтрует открытую таблицу. Enter применяет запрос сразу, ввод — с небольшой задержкой. Очистка запроса показывает неотфильтрованные данные с первой порции. Ширина строки и место единственной кнопки очистки стабильны.

Новый запрос, таблица или файл отменяют прежнее чтение. Переключение вкладки интерфейса не отменяет и не повторяет его. `/` переводит фокус в поиск, `Esc` снимает фокус с поля, не скрывая данные. Стрелки листают порции только в исследовании файлов и вне полей ввода.

Область данных занимает всё доступное пространство под шапкой. Страница ограничена вьюпортом, таблица прокручивается внутри своей области. Большие кнопки предыдущей и следующей порции закреплены снизу поверх данных. Длинные ячейки раскрываются кликом.

## Плагины, языки и темы

«Модуль» в прежнем API и «плагин» обозначают одно расширение. Плагины могут влиять на **любые элементы интерфейса**: навигацию, тулбар, поиск, данные, пагинацию, настройки и оформление. Также они могут добавлять новые элементы и разделы настроек. Интерпретаторы и виды сохраняют прежний контракт.

Общий реестр — `Bouquet.plugins`. Необязательный `setup(ui)` вызывается один раз, когда интерфейс и его действия готовы, в том числе для плагинов, загруженных во время работы. `ui` предоставляет корень приложения, документ, ссылки на основные области, действия и `addTab`/`selectTab`. Панель новой вкладки монтируется один раз. Событие `view:render` позволяет дорабатывать заново отрисованные данные.

Темы — обычные плагины с `kind: 'plugin'`, `category: 'theme'` и CSS. Они загружаются общей кнопкой плагинов и отображаются в разделе «🎨 Темы оформления». Одновременно активна одна тема; при смене её CSS заменяется. В комплекте — системная, светлая и тёмная темы в `modules/themes.js`. Базовые стили ядра обеспечивают рабочий интерфейс и без них.

Подключение темы, языка или интерфейсного плагина не переоткрывает файл и не сбрасывает результаты. Новый интерпретатор переоткрывает текущий источник с сохранением запроса и таблицы; новый вид или поиск обновляет отображение. Плагины выполняются как JavaScript приложения и имеют доступ ко всей странице, изоляция не предусмотрена.

Пример интерфейсного плагина — `modules/hello.js`, не подключённый по умолчанию. Загрузка через настройки добавляет раздел «👋 Hello». Он показывает постоянную панель, переводит текст при смене языка и возвращает к сохранённому просмотру. Исходник содержит комментарии к регистрации, `setup`, `ui.addTab` и событиям; инструкции находятся в обоих README и подробной документации.

## Язык интерфейса

В ядре (`core/i18n.js`) зарегистрированы пакеты «Русский» и «English» с `kind: 'plugin'`, `category: 'language'`, `locale` и словарём `messages`. По умолчанию выбран русский. Другие языки подключаются обычными `.js`-плагинами и появляются в разделе «🌐 Язык». У пакета уникальный id и корректный языковой тег locale; недостающие переводы берутся из английского словаря. Названия языков показываются на родном языке.

«Применить» меняет подписи, подсказки, доступные имена, состояния, прогресс, каталоги расширений и окно связей без повторного чтения и без пересоздания таблицы. Сохраняются файл, таблица, запрос, порция, раскрытые ячейки и прокрутка; начатое чтение продолжается. Имена файлов, таблиц, пользовательских колонок и содержимое данных не переводятся. Обновляется атрибут `html.lang`. Выбор языка и темы действует в текущей сессии страницы.

`Bouquet.i18n.t(key, params)` получает строку, `bind(element, key, params)` связывает текст элемента с текущим языком; для разметки есть атрибуты `data-i18n`, `data-i18n-title`, `data-i18n-aria-label`, `data-i18n-placeholder`. Значения подставляются как текст. Числа и множественные формы форматируются для выбранного locale. Событие `language:change` передаёт `{id, locale}`. `ui.setLanguage(id)` применяет зарегистрированный пакет.

## CronosPro — плагин `cronos.js`

Многокомпонентный интерпретатор получает выбранный набор файлов через `open({source, name, files, signal})`, где `files` содержит `{name, open(signal)}`. Для CronosPro нужны пары CroStru и CroBank, CroIndex необязателен. Все компоненты выбираются вместе; соседние базы в подкаталогах не смешиваются. Интерпретатор группирует компоненты по директории: 12 файлов двух баз показываются как два элемента списка, шесть файлов одной базы открывают её сразу. При нескольких таблицах следующим шагом показывается выбор таблицы. Группа подписана путём папки, а без пути — «CronosPro». Исходные компоненты сохраняются отдельно от отображаемых элементов; обычные файлы в том же наборе остаются отдельными сущностями. Если компонентов не хватает, ошибка перечисляет их и содержит ссылку «Открыть» для повторного выбора всей группы.

Плагин читает версии 01.02/01.03/01.04/01.05/01.11, схему полей, Windows-1251, цепочки расширенных записей и сжатые блоки с CRC. Записи выдаются асинхронными порциями, поддерживают поиск, прогресс и отмену. Файлы находятся в памяти, кеш декодированных записей ограничен 4 МиБ. Проверка на локальной Chel2006obl дала 3 таблицы с 23/13/11 полями; первые 200 записей каждой совпали с cronodump по контрольным суммам.

Стандартный KOD применяется без вопроса. Для защищённых вариантов автоматически пробуются частотное восстановление по схеме и восстановление по заголовкам сжатых записей. Неполные или непроверенные таблицы не принимаются. При неудаче доступен диалог ввода готовой KOD-таблицы (512 hex-символов), с проверкой и отменой; значение не сохраняется. **Часть пункта 7 о вводе обычного пароля пока не реализована:** в выбранном cronodump нет преобразования пароля в KOD. Диалог явно сообщает об ограничении.

## Связи таблиц — плагин `links.js`

В начале ячейки с объявленным внешним ключом или ключом, на который ссылаются другие таблицы, появляется иконка связи. Клик открывает справа дровер с найденными записями соседней таблицы этой же базы. Для нескольких связей показаны отдельные группы; поля составного ключа сопоставляются совместно. Связи определяются по `FOREIGN KEY`/`REFERENCES` в схеме SQLite, без догадок по именам колонок.

Дровер читает данные независимо от основного поиска, порциями по 50 записей, показывает прогресс и отсутствие совпадений. Закрытие, смена файла, таблицы, запроса или вкладки отменяют чтение. Данные основного исследования сохраняются. Поддерживаются оба режима загрузки SQLite; плагин можно подключить и после открытия файла.

## Настройки чтения

SQLite до 100 МиБ включительно по умолчанию читает `sqlite_full_load.js`, большие файлы — `sqlite.js`. Галочка «Прогрессивная загрузка» находится во вкладке «Настройки». Для других форматов она недоступна.

Смена режима переоткрывает текущий источник, сохраняя запрос и выбранную таблицу; пагинация начинается заново. Новый файл снова выбирает режим автоматически. Прогрессивный режим можно включить вручную и для маленьких баз.

## Сборки и релизы

`VERSION` содержит текущую стабильную версию `X.Y.Z`; она совпадает с `Bouquet.version` в ядре. `CHANGELOG.md` хранит датированные заметки по версиям на русском и английском. Публикация запускается push тега `vX.Y.Z`, соответствующего версии и разделу истории. Изменения веток и pull request проходят те же тесты и сборку без публикации.

`scripts/build.py` использует только стандартную библиотеку Python и создаёт `dist/bouquet-X.Y.Z-ru.zip`, `dist/bouquet-X.Y.Z-en.zip`, контрольные суммы SHA-256 и дерево GitHub Pages. Архивы включают все модули, локальные зависимости с лицензиями и только демонстрационные `data/example.db`/`data/example.csv`. Локальные базы и служебные файлы не публикуются. Выбранный язык задаётся через `html.lang`; переключение языка остаётся доступным. Исходники работают и без сборки.

Workflow `.github/workflows/release.yml` проверяет приложение и дистрибутивы, публикует один GitHub Release с двумя отдельными ZIP (RU/EN) и контрольными суммами, независимо разворачивает Pages: русский вариант в корне, английский в `/en/`. В Actions языковые сборки также загружаются отдельными артефактами. Release notes хранятся только в `CHANGELOG.md` репозитория: в архивы, Pages и описание релиза они не включаются. В настройках репозитория один раз нужно выбрать источник Pages «GitHub Actions» и разрешить теги в окружении `github-pages`. Инструкция подготовки версии и локальной сборки — в README.

## Архитектура данных

- `core/bouquet.js` — реестр плагинов, события, утилиты, встроенный текстовый интерпретатор и вид.
- `core/i18n.js` — встроенные русский и английский пакеты, переводы, форматы чисел и API языковых плагинов.
- `core/sources.js` — источники байтов Blob/File и HTTP Range.
- `core/files.js` — списки выбранных файлов и обход перетащенных папок.
- `core/ui.js` — шапка, постоянные панели, навигация, отдельные каталоги языков, плагинов и тем, API расширения интерфейса.
- `core/app.js` — открытие файлов, поиск, отмена чтения и асинхронная пагинация.
- `styles/app.css` — базовый внешний вид и адаптивная компоновка.

Интерпретатор предоставляет `open({source, signal})` или прежний `parse({buffer})`. Таблица предоставляет `read({cursor, limit, match, signal, onProgress})` или массив `rows`. Ядро хранит курсоры перехода назад, отменяет устаревшие запросы и передаёт виду только текущую порцию.

SQLite читает схему и необходимые страницы b-дерева, кеширует до 4 МиБ страниц; отдельная запись ограничена 64 МиБ. Неявного ограничения миллионом строк нет. Поиск отдаёт управление браузеру каждые 128 записей и сообщает промежуточные результаты. До конца обхода количество совпадений приблизительное, число страниц может быть неизвестно.

Выбранные локальные файлы читаются через `Blob.slice`. Стандартный системный диалог поддерживает множественный выбор файлов (`multiple`). Перетаскивание папок обходит все порции файлов и вложенные папки. `.js` в списке папки открывается как данные, а не выполняется; для подключения плагина есть отдельная кнопка. HTTP-источник использует Range при поддержке сервером, иначе скачивает файл целиком в Blob с уведомлением. CSV/TSV и текст пока целиком в памяти. Worker и поисковый индекс пока не используются.

Полный контракт плагинов и команды проверки — в `docs/DEVELOPMENT_RU.md`. README.md и README_RU.md содержат короткое описание, ссылки выбора языка в самом начале, адрес GitHub Pages и ссылку на подробную документацию. Инструкции локального сервера и релизов вынесены в `docs/` и входят в дистрибутивы.
