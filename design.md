# 💐 Bouquet — концепция

## Принципы

1. Компактное ядро, без установки приложения и без сборки.
2. Открывается в браузере на любой ОС, работает офлайн.
3. Данные выбранных локальных файлов остаются в браузере.
4. Функции и оформление добавляются плагинами — отдельными JavaScript-файлами.
5. Файл показывается сразу после открытия; поиск уточняет уже видимые данные.

## Структура интерфейса

Слева расположен открытый по умолчанию сайдбар. В нём три встроенные вкладки:

- **Исследование файлов** — основная, выбрана при запуске.
- **Плагины** — список подключённых плагинов, загрузка `.js` и применение тем.
- **Настройки** — параметры чтения файлов и выбор темы среди подключённых плагинов.

Кнопка в заголовке сайдбара сворачивает его до узкой полосы с иконками, освобождая место данным. Повторное нажатие возвращает подписи. В свёрнутом состоянии доступны все вкладки; у кнопок есть подсказки и доступные имена. Внизу открытого сайдбара — @vladaaar, 2026.

Вкладки меняют видимую панель без навигации и перезагрузки страницы. Панели создаются один раз и остаются в DOM. Переход из исследования в настройки или плагины и обратно сохраняет файл, выбранную таблицу, введённый запрос, результаты, порцию данных, раскрытые ячейки и прокрутку. Текущее чтение продолжается в фоне. Сворачивание сайдбара также не запускает повторное чтение.

Это сохранение состояния в текущей сессии страницы, а не восстановление после её перезагрузки.

## Исследование файлов

### Нет доступного файла

В центре рабочей области — большая кнопка с иконкой загрузки «Открыть файл». Рядом пояснение: файл можно выбрать с диска или перетащить в окно. Строка поиска и пустая таблица не отвлекают от выбора файла.

На `file://` браузер не даёт автоматически читать соседние файлы: показываем кнопку ручного выбора. При запуске через HTTP ядро пробует файлы из `bouquet.files.json`. Если ни один не доступен, возвращаемся к кнопке открытия. Доступность файла нельзя выводить только из наличия его имени в манифесте.

### Файл выбран или загружен

Сразу после разбора показываем первую порцию данных — до 100 строк, без ввода поискового запроса. Для прогрессивного источника читается первая порция, для CSV/TSV и текста файл пока разбирается целиком. Состояние чтения отображается спиннером и статусом; ошибки показываются явно, остаётся возможность выбрать другой файл.

Сверху рабочей области:

- Чип: индикатор состояния → файл → таблица, если их несколько → интерпретатор.
- Поиск, если подключён поисковый плагин. Слева — 💐 с подсказкой «💐 Bouquet, @vladaaar, 2026».
- Статус чтения и прогресса.

Клик по имени файла открывает выбор другого файла. Клик по интерпретатору остаётся быстрым способом подключить `.js`; основной каталог подключённых расширений находится во вкладке «Плагины».

Индикатор: зелёный — файл и интерпретатор готовы; жёлтый — подходящий формат не распознан; красный — файла нет или возникла ошибка; спиннер — идёт чтение.

### Поиск и отображение

Поиск фильтрует открытую таблицу. Enter применяет запрос сразу, ввод — с небольшой задержкой. Очистка запроса показывает неотфильтрованные данные с первой порции. Ширина строки и место единственной кнопки очистки стабильны.

Новый запрос, таблица или файл отменяют прежнее чтение. Переключение вкладки интерфейса не отменяет и не повторяет его. `/` переводит фокус в поиск, `Esc` снимает фокус с поля, не скрывая данные. Стрелки листают порции только в исследовании файлов и вне полей ввода.

Область данных занимает всё доступное пространство справа от сайдбара. Страница ограничена вьюпортом, таблица прокручивается внутри своей области. Большие кнопки предыдущей и следующей порции закреплены снизу поверх данных. Длинные ячейки раскрываются кликом.

## Плагины и темы

«Модуль» в прежнем API и «плагин» обозначают одно расширение. Плагины могут влиять на **любые элементы интерфейса**: навигацию, тулбар, поиск, данные, пагинацию, настройки и оформление. Также они могут добавлять новые элементы и вкладки сайдбара. Интерпретаторы и виды сохраняют прежний контракт.

Общий реестр — `Bouquet.plugins`. Необязательный `setup(ui)` вызывается один раз, когда интерфейс и его действия готовы, в том числе для плагинов, загруженных во время работы. `ui` предоставляет корень приложения, документ, ссылки на основные области, действия и `addTab`/`selectTab`. Панель новой вкладки монтируется один раз. Событие `view:render` позволяет дорабатывать заново отрисованные данные.

Темы — обычные плагины с `kind: 'plugin'`, `category: 'theme'` и CSS. Они загружаются той же кнопкой и отображаются в том же списке. Одновременно активна одна тема; при смене её CSS заменяется. В комплекте — системная, светлая и тёмная темы в `modules/themes.js`. Базовые стили ядра обеспечивают рабочий интерфейс и без них.

Подключение темы или интерфейсного плагина не переоткрывает файл и не сбрасывает результаты. Новый интерпретатор переоткрывает текущий источник с сохранением запроса и таблицы; новый вид или поиск обновляет отображение. Плагины выполняются как JavaScript приложения и имеют доступ ко всей странице, изоляция не предусмотрена.

## Связи таблиц — плагин `links.js`

В начале ячейки с объявленным внешним ключом или ключом, на который ссылаются другие таблицы, появляется иконка связи. Клик открывает справа дровер с найденными записями соседней таблицы этой же базы. Для нескольких связей показаны отдельные группы; поля составного ключа сопоставляются совместно. Связи определяются по `FOREIGN KEY`/`REFERENCES` в схеме SQLite, без догадок по именам колонок.

Дровер читает данные независимо от основного поиска, порциями по 50 записей, показывает прогресс и отсутствие совпадений. Закрытие, смена файла, таблицы, запроса или вкладки отменяют чтение. Данные основного исследования сохраняются. Поддерживаются оба режима загрузки SQLite; плагин можно подключить и после открытия файла.

## Настройки чтения

SQLite до 100 МиБ включительно по умолчанию читает `sqlite_full_load.js`, большие файлы — `sqlite.js`. Галочка «Прогрессивная загрузка» находится во вкладке «Настройки». Для других форматов она недоступна.

Смена режима переоткрывает текущий источник, сохраняя запрос и выбранную таблицу; пагинация начинается заново. Новый файл снова выбирает режим автоматически. Прогрессивный режим можно включить вручную и для маленьких баз.

## Архитектура данных

- `core/bouquet.js` — реестр плагинов, события, утилиты, встроенный текстовый интерпретатор и вид.
- `core/sources.js` — источники байтов Blob/File и HTTP Range.
- `core/ui.js` — постоянные панели, навигация, каталог плагинов, темы и API расширения интерфейса.
- `core/app.js` — открытие файлов, поиск, отмена чтения и асинхронная пагинация.
- `styles/app.css` — базовый внешний вид и адаптивная компоновка.

Интерпретатор предоставляет `open({source, signal})` или прежний `parse({buffer})`. Таблица предоставляет `read({cursor, limit, match, signal, onProgress})` или массив `rows`. Ядро хранит курсоры перехода назад, отменяет устаревшие запросы и передаёт виду только текущую порцию.

SQLite читает схему и необходимые страницы b-дерева, кеширует до 4 МиБ страниц; отдельная запись ограничена 64 МиБ. Неявного ограничения миллионом строк нет. Поиск отдаёт управление браузеру каждые 128 записей и сообщает промежуточные результаты. До конца обхода количество совпадений приблизительное, число страниц может быть неизвестно.

Выбранные локальные файлы читаются через `Blob.slice`. HTTP-источник использует Range при поддержке сервером, иначе скачивает файл целиком в Blob с уведомлением. CSV/TSV и текст пока целиком в памяти. Worker и поисковый индекс пока не используются.

Полный контракт плагинов и команды проверки — в README.md.
