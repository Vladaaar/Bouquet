# 💐 Bouquet

Лёгкий модульный просмотрщик файлов в браузере. Работает офлайн, не требует установки приложения или сборки. Поддерживает SQLite, CSV/TSV и простой текст; форматы, поиск и способы отображения подключаются отдельными JavaScript-модулями.

## Запуск

Откройте `index.html`, затем нажмите «📂 Открыть» и выберите один или несколько файлов либо перетащите файлы в окно. Если файлов или таблиц несколько, выберите нужную из списка; после этого появится первая порция данных. Сохраняйте структуру папок при копировании приложения.

Чтобы показывать доступные файлы из `bouquet.files.json`, запустите локальный HTTP-сервер:

```sh
python3 -m http.server 8000
# Откройте http://localhost:8000
```

На `file://` браузер не разрешает автоматически читать соседние базы. Ручной выбор файла работает без сервера. Данные выбранных файлов не отправляются на сервер.

├── bouquet.files.json     список файлов проекта
├── data/                  файлы с данными
├── modules/
│   ├── sqlite.js          прогрессивное чтение SQLite 3
│   ├── sqlite_full_load.js полная загрузка SQLite в память

│   ├── links.js           связи SQLite-таблиц и дровер связанных записей

Разметку, стили, ядро и модули можно обновлять отдельными файлами. Порядок подключения: `bouquet.js`, `sources.js`, `files.js`, модули, `ui.js`, `app.js`. Для новой асинхронной версии SQLite нужны совместимые файлы ядра и табличного вида из версии 1.1.

Модули подключены обычными `<script src="…">`: сборщик и сеть для них не нужны. Чтобы убрать модуль, удалите его подключение из HTML; чтобы добавить — включите свой файл. Кнопка «Подключить плагин .js» в разделе «Плагины» на странице настроек позволяет подключить `.js` во время работы.

## Использование

- Шапка просмотра: `[💐 Bouquet] [набор / файл / таблица] [📂 Открыть] [⚙]`. Путь находится слева, действия — справа. Родительские части пути возвращают к спискам, текущая часть не выполняет действий. На узком экране путь переносится на следующую строку.
- На пустом экране «📂 Открыть» находится по центру; после загрузки кнопка расположена в шапке. Она сразу вызывает стандартный диалог с множественным выбором файлов. Отмена выбора сохраняет текущие данные. Отдельной ссылки на выбор папки нет; перетаскивание папок с вложенными файлами поддерживается.
- В настройках шапка показывает `💐 Bouquet / Настройки` и крестик возврата. Файловые действия скрыты. Крестик и логотип возвращают к сохранённому просмотру. Авторство — в подсказке иконки логотипа и внизу настроек.
- Несколько файлов или таблиц показываются списком в зоне просмотра. Выберите сущность, чтобы открыть первые 100 строк. Единственный файл или таблица открывается сразу. Родительские части пути в шапке возвращают к спискам таблиц или файлов и отменяют чтение. Содержимое локального файла не читается до выбора.
- `.js` из списка папки открывается как текст. Плагины подключаются отдельной кнопкой в настройках; одиночный `.js`, выбранный через «Открыть» или перетащенный в окно, также подключается как плагин.
- Введите запрос для фильтрации; Enter применяет его сразу. Пустой запрос показывает все строки с пагинацией.
- Переключение вкладок сохраняет файл, таблицу, запрос, результаты, текущую порцию, раскрытые ячейки и прокрутку. Страница не перезагружается; чтение продолжается в фоне.
- На странице настроек собраны режим чтения, тема и раздел «Плагины» с карточками всех подключённых расширений. Ссылка на автора находится внизу настроек.
- Поиск: слова через пробел означают И, `"точная фраза"`, `-исключение`, `колонка:значение`. Имя колонки можно сократить до префикса.
- Очистка поиска оставляет таблицу открытой.
- Внизу — предыдущая и следующая порции по 100 строк. Работают также стрелки клавиатуры, если фокус не в поле поиска.
- `/` переводит фокус в поиск, `Esc` снимает фокус с поля поиска, сохраняя данные.
- Таблицы одной базы выбираются из списка в зоне просмотра; для смены таблицы нажмите имя базы в пути. Длинные ячейки раскрываются кликом.
- Индикатор, количество строк и столбцов, число совпадений и прогресс собраны в одной строке над данными. Во время прогрессивного чтения индикатор вращается, ввод остаётся доступен. Новый запрос, таблица или файл отменяют прежнее чтение. Во время поиска показываются прогресс и уже найденные строки текущей порции.

Страница занимает высоту вьюпорта, вертикально прокручивается только область данных. Широкая таблица расширяется за обычный блок до доступной ширины окна; если этого недостаточно, внутри появляется горизонтальная прокрутка. Пагинация лежит поверх таблицы без зарезервированного отступа. Поле поиска сохраняет ширину при появлении кнопки очистки; встроенный крестик браузера отключён.

## Связи между таблицами

Плагин `modules/links.js` подключён в `index.html`. В начале ячеек, участвующих в объявленной связи SQLite (`FOREIGN KEY` / `REFERENCES`), появляется кнопка 🔗. Нажмите её: справа откроется дровер с полями связанных записей из той же базы. Для родительского ключа показаны ссылающиеся на него записи, для внешнего ключа — родительские. Поддерживаются составные ключи, ссылки на первичный ключ без явного списка столбцов и связи таблицы с самой собой.

Связанные записи читаются независимо от основного поиска, по 50 за раз; кнопка «Следующие 50» показывает следующую порцию. В больших базах поиск может потребовать последовательного обхода связанной таблицы. Дровер сообщает прогресс; ×, Esc или клик вне панели закрывают его и отменяют чтение. Смена файла, запроса, таблицы или вкладки также закрывает дровер. Основная таблица и её пагинация от этого не меняются.

Без объявленных внешних ключей плагин не угадывает связи по названиям столбцов. `NULL` не связывается с пустой строкой. Поддерживаются скалярные ключи и встроенные сравнения `BINARY`, `NOCASE` (ASCII), `RTRIM`; бинарные BLOB-ключи и пользовательские collations не поддерживаются. Это разбор схемы и сопоставление значений без SQL-движка.

SQLite-интерпретаторы передают `table.schemaSQL` (исходный `CREATE TABLE`) и сохраняют `null` в данных. Плагин извлекает метаданные связей один раз на открытый набор таблиц. Табличный вид помечает ячейки атрибутами `data-bq-row` (исходный номер строки) и `data-bq-column` (индекс столбца с нуля); собственные виды могут использовать эти атрибуты для совместимости с плагином.

В примере `data/example.db` таблица `purchases` содержит 65 покупок: `flower_id` ссылается на `stock.id`, `quantity` — количество купленных цветов, `purchased_on` — дата. Нажмите 🔗 у `purchases.flower_id`, чтобы увидеть цветок, или у `stock.id`, чтобы увидеть его покупки. У пиона (`id = 1`) 53 покупки — можно проверить переход ко второй порции; у эвкалипта (`id = 8`) покупок нет — можно проверить пустой результат. Через HTTP выберите эту базу в списке доступных файлов манифеста; без сервера выберите её вручную.

## Большие SQLite-файлы

Режим выбирается автоматически для каждого нового SQLite-файла: **до 100 МиБ включительно — полная загрузка в память**, больше — прогрессивное чтение. На вкладке «Настройки» галочка «Прогрессивная загрузка» показывает текущий режим и позволяет переключить его вручную. Файл переоткрывается с сохранением запроса и выбранной таблицы; пагинация начинается заново. Ручной выбор действует для текущего файла, новый файл снова использует автоматический режим. Для других форматов переключатель недоступен.

Полная загрузка использует `modules/sqlite_full_load.js`: все строки загружаются заранее, точное количество известно сразу. Во время синхронного разбора интерфейс может ненадолго приостановиться. Размер файла не равен объёму памяти декодированных данных.

В прогрессивном режиме SQLite-модуль сначала читает заголовок и схему. Строки выбранной таблицы извлекаются только по запросу интерфейса. Обход b-дерева использует курсор; переход назад перечитывает нужную порцию по сохранённому курсору. В этом режиме полный массив строк не создаётся.

Кеш страниц ограничен **4 МиБ**. Дополнительно в памяти находятся схема, курсоры посещённых порций, текущие строки и временные данные записей. Это не общий лимит памяти приложения. Отдельная запись размером более **64 МиБ** вызывает явную ошибку. Прежнее неявное усечение таблицы на миллионе строк убрано.

Общее количество строк и страниц заранее неизвестно: сначала пагинатор показывает `1 / …`. После достижения конца известен точный размер результата. Поиск произвольной подстроки последовательно проверяет записи, отдаёт управление интерфейсу каждые 128 обработанных строк и поддерживает отмену. Для редкого совпадения или его отсутствия может потребоваться полный обход таблицы. Это асинхронная обработка в основном потоке, без Web Worker и без поискового индекса.

Источники файла:

- **Ручной выбор или перетаскивание:** чтение нужных диапазонов через `Blob.slice()`, без предварительного `arrayBuffer()` всего файла.
- **HTTP-сервер с Range:** загрузка необходимых диапазонов по сети.
- **HTTP-сервер без Range:** загрузка целого файла в Blob, затем ленивый разбор. Интерфейс сообщает об этом. Обычный `python3 -m http.server` может работать именно в таком режиме; для гарантированного локального чтения по частям выберите файл вручную.

CSV/TSV и текст сохраняют прежнюю модель: файл целиком в памяти. Ленивое чтение этих форматов пока не реализовано.

### Возможности SQLite-модуля

Модуль читает формат файла напрямую, без зависимостей, WASM и SQL-движка: страницы таблиц, overflow-страницы, значения записей, `INTEGER PRIMARY KEY` и обычные таблицы `WITHOUT ROWID`, включая составные ключи. Порядок колонок `WITHOUT ROWID` восстанавливается по объявлению ключа. BLOB отображается как `‹blob N Б›`, целые числа вне безопасного диапазона JavaScript — строкой.

Это просмотрщик сохранённого файла: SQL-запросы и представления не вычисляются, редактирования нет, WAL-файлы не подключаются. Используйте самостоятельную согласованную копию базы. Разбор `CREATE TABLE` упрощён; виртуальные таблицы, generated-колонки и все варианты SQL-синтаксиса не поддерживаются полноценно.

Ошибка `Maximum call stack size exceeded` на больших таблицах была вызвана передачей всех длин строк в `Math.max(...array)`. Новый путь чтения не использует такой вызов и не обходит все строки ради определения ширины таблицы.

## API плагинов, версия 1.2

Глобальный объект `Bouquet` предоставляет `register`, события `on`/`emit`, `exec` и `util`. Побеждает подходящий интерпретатор или вид с наибольшим `priority`; для интерпретаторов одной группы `format` ядро выбирает нужный `loadingMode` (`memory` или `progressive`), если такой модуль подключён; встроенные имеют `priority: -100`.

### Интерфейсные плагины и темы

Все расширения регистрируются через `Bouquet.register` и доступны в `Bouquet.plugins`. `id` должен быть уникальным. Прежние `interpreter`, `renderer` и `feature` продолжают работать. Любой плагин может предоставить `setup(ui)`: ядро вызывает его один раз после подготовки интерфейса и действий, в том числе при загрузке `.js` во время работы.

```js
Bouquet.register({
  kind: 'plugin', id: 'notes', name: 'Заметки',
  setup(ui) {
    ui.addTab({
      id: 'notes', label: 'Заметки', icon: '✎',
      mount(panel) {
        const input = document.createElement('textarea');
        input.setAttribute('aria-label', 'Заметки');
        panel.appendChild(input);
      }
    });
  }
});
```

`ui.addTab({id, label, icon, mount})` создаёт постоянную панель и кнопку в навигации разделов плагинов на странице настроек, возвращает панель. Вместо создания можно передать существующий DOM-элемент `panel`. `mount(panel, ui)` вызывается только один раз; переключение через `ui.selectTab(id)` сохраняет DOM и локальное состояние. Встроенные id: `explorer`, `settings`; прежний `plugins` в `selectTab` открывает настройки. Выбранный раздел — `ui.activeTab`.

Расширения могут менять любую часть страницы: `ui.root`, `ui.document`, `ui.elements` (`header`, `navigation`, `workspace`, `explorer`, `plugins`, `settings`, `toolbar`, `stage`, `pager`). Действия: `ui.actions.openFile(file)`, `ui.actions.openFiles(files, {folder: true})` (массив File с `webkitRelativePath` для папки) и `ui.actions.refresh()`. `Bouquet.ui` доступен после загрузки `core/ui.js`, действия готовы к вызову `setup`.

События: `ui:ready` передаёт `ui`, `tab:change` — `{id}`, `theme:change` — `{id}`, `view:render` — `{host, view}` после отрисовки порции или промежуточных результатов. `view:reset` уведомляет о начале обновления данных. `ui.currentView` содержит последний `{host, view}` для подключения плагинов к уже открытой таблице. Для изменений внутри заново создаваемой таблицы используйте `view:render`.

Тема — такой же загружаемый плагин:

```js
Bouquet.register({
  kind: 'plugin', category: 'theme', id: 'theme-rose', name: 'Роза',
  css: ':root { --canvas: #fff0f4; --surface: #fff; --ink: #351b28; --iris: #ac3968; color-scheme: light; }'
});
```

`ui.setTheme(id)` применяет CSS выбранной темы, заменяя CSS предыдущей. Тема может стилизовать любые элементы. Встроенные темы поставляются отдельным файлом `modules/themes.js`; по умолчанию выбрана системная. Подключение или смена темы не перечитывает файл. Настройки темы и навигации действуют в текущей сессии страницы.

Плагины исполняются с доступом ко всей странице; подключайте доверенный код. Это механизм расширения интерфейса без изоляции. Подключение интерпретатора переоткрывает файл с сохранением таблицы и запроса; подключение вида или поиска обновляет текущую порцию.

### Прежний интерфейс: массив строк

Продолжает работать без изменений для интерпретаторов:

```js
Bouquet.register({
  kind: 'interpreter', id: 'json', name: 'JSON', priority: 20,
  test({ ext, bytes }) { return ext === 'json'; },
  parse({ buffer, name, signal }) {
    const rows = JSON.parse(Bouquet.util.decode(buffer));
    return { name, tables: [{
      name, columns: Object.keys(rows[0] || {}),
      rows: rows.map(row => Object.values(row))
    }] };
  }
});
```

`test` получает первые 4096 байт, имя и расширение. Для `parse` ядро читает полный буфер; `parse` может возвращать Promise.

### Новый интерфейс: источник строк

Если интерпретатор предоставляет `open`, ядро вызывает его вместо `parse`:

```js
async open({ source, name, ext, bytes, signal }) {
  // source: { name, size, read(offset, length, { signal }) }
  // read возвращает Promise<Uint8Array>.
  return {
    name,
    tables: [{
      name: 'Данные', columns: ['Название'],
      async read({ cursor, limit, match, signal, onProgress }) {
        // cursor === null: начать с начала; иначе продолжить обход.
        // match(cells): синхронный предикат, либо undefined.
        // Проверять signal и периодически отдавать управление браузеру.
        return {
          rows: [{ n: 1, cells: ['Пример'] }],
          nextCursor: null,
          hasMore: false,
          total: 1
        };
      }
    }],
    close() { /* освободить кеши и ресурсы при смене файла */ }
  };
}
```

Контракт `read`:

- Возвращает максимум `limit` подходящих строк. `n` — номер исходной строки, начиная с 1; `cells` — значения в порядке `columns`.
- `nextCursor` нужен, если `hasMore === true`. Курсор непрозрачен для ядра, относится к конкретной таблице и запросу; повторное чтение с ним должно воспроизводить ту же порцию, не изменяя сам переданный курсор.
- `total` — необязательное точное число всех строк таблицы, а не число совпадений. Для отфильтрованного результата количество определяется ядром после достижения конца.
- Прогресс: `onProgress({ scanned, found, rows })`, где `rows` — накопленные строки текущей порции, `found` — их количество, `scanned` — число просмотренных строк от начала таблицы.
- Отмена: ошибка с `name: 'AbortError'`. Ядро также отбрасывает результаты устаревших запросов.

`Bouquet.util.blobSource(file)` создаёт локальный источник; `urlSource(url, { signal })` — HTTP-источник. `checkAbort(signal)` проверяет отмену.

### Отображение и поиск

```js
Bouquet.register({
  kind: 'renderer', id: 'cards', name: 'Карточки', priority: 15,
  test(table) { return !table.plain; },
  render(host, view) { /* показать view.rows */ }
});
```

Вид должен использовать **`view.rows`**, а не `table.rows`: у ленивых таблиц массива `rows` нет. Поля вида: `table`, `dataset`, `rows`, `query`, `page`, `pageSize`, `total`, `found`, `foundExact`, `pages`, `hasMore`, `highlight`. `total` и `pages` могут быть неизвестны, а при промежуточном прогрессе `hasMore` ещё не определён. `foundExact: false` означает нижнюю границу числа совпадений. `highlight(value)` возвращает экранированный HTML с подсветкой.

Модуль поиска может предоставлять `compile(table, query) → match(cells)` для работы без полного массива. Старые `filter(table, query) → индексы` и `highlight(value, query)` сохраняются; для старого фильтра на ленивом источнике есть адаптер, передающий по одной строке. Фильтры, зависящие от соседних строк или всей таблицы, требуют собственного `compile`.

## Проверки

Нужны Node.js с `node:test` и Python 3 со стандартным модулем `sqlite3`. Внешние зависимости не устанавливаются:

```sh
node --test tests/*.test.cjs
```

Тесты создают временные SQLite-базы, проверяют курсоры, поиск, отмену, переполнение страниц, составные ключи, источники HTTP/Blob и совместимость старого API. При наличии `data/new1_Chel2006.sqlite3` проверяются ленивое открытие и полный обход с ожидаемыми количествами строк: 205907, 205727 и 3. Значения пользовательских записей не печатаются. Тесты логики интерфейса используют минимальную модель DOM и не заменяют визуальную проверку браузером.
